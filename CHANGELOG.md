# Changelog

All notable changes to Aristo are recorded here. **Every commit adds one bullet** to the `## [Unreleased]` section, in customer-facing language. At release time, `[Unreleased]` is promoted to a versioned section and should read coherently as a release-note draft.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Pre-`0.1.0` is the initial bootstrap series (per `docs/ROADMAP.md` and `CLAUDE.md` §11).

See [`CLAUDE.md`](./CLAUDE.md) §3 for the discipline.

### Added
- docs: `docs/GETTING-STARTED.md` — the agent-first walkthrough. Centers the real workflow: your coding agent writes `#[aristo::intent]` claims (authoring skill), verifies them and brings each verdict back for you to **accept or refuse** (neural-verify + critique skills), and the git pre-commit hook re-stamps on every commit so you never run `aristo stamp` by hand. Two new flags on `aristo stamp`: `--skip-canon` (silent per-invocation opt-out, conflicts-with `--refresh-canon`) and `--refresh-canon` (invalidate all cached entries and re-query). `aristo stamp --check` keeps the existing read-only invariant — canon-match step doesn't run under `--check` so CI never makes outbound network calls. Cache writes through `CanonMatchesFile::write_atomic` (PR #4): temp-then-rename, parent-dir creation, no orphan `.tmp`. Cache reads use the existing-or-default pattern so a first-run is just an empty `CanonMatchesFile`. Merge semantics preserve user decisions: each batched annotation's `pending_matches` are replaced by the new response, while `accepted_matches` and `rejected_matches` for the same annotation pass through untouched (regression would silently undo review work on every stamp). Rejection-suppression at merge time: candidates whose `(canon_id, text_hash)` is in the entry's `rejected_matches` get filtered out of pending so a previously-rejected match doesn't re-surface until the user changes the annotation text. Canon-bound ids (`aristos:`, `kanon:`) are excluded from the batch entirely — those are bound to a canon entry already; the version-migration path (PR #12) handles their refresh. `applies_to_from_site` derives the surface keyword (`fn`/`struct`/`method`/etc.) from the index entry's `site` string and includes it in the API call so the server can filter against the canon entry's `applies_to` set. Two new helpers on `Workspace`: `canon_matches_path()` returns `.aristo/canon-matches.toml`. New user-facing summary printer `print_stamp_summary` renders the six `CanonStepOutcome` variants (`Ok` / `CacheHit` / `DisabledByConfig` / `SkippedByFlag` / `FreeTier` / `Degraded`) per Flow 1/2/6 in cli-sessions.md byte-for-byte.
