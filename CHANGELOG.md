# Changelog

All notable changes to Aristo are recorded here. **Every commit adds one bullet** to the `## [Unreleased]` section, in customer-facing language. At release time, `[Unreleased]` is promoted to a versioned section and should read coherently as a release-note draft.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Pre-`0.1.0` is the initial bootstrap series.

See [`CLAUDE.md`](./CLAUDE.md) §3 for the discipline.

## [Unreleased]

### Added
- repo: initial repository scaffold — LICENSE (MIT), README, `.gitignore`, this CHANGELOG, and `CLAUDE.md` working agreement.
- build: four-crate Cargo workspace (`aristo`, `aristo-core`, `aristo-macros`, `aristo-cli`) per K3 — empty skeletons; `cargo fmt`/`check`/`clippy -D warnings`/`test` all green. CLI binary stubbed to exit 1 with "not yet implemented".
- test: integration test harness for the CLI — `trycmd` for declarative `console`-fenced session scenarios (sourced from `docs/mockups/`), `assert_cmd` + `predicates` for imperative tests. Convention: `tests/cmd/active/*.md` runs and must pass; `tests/cmd/_pending/*.md` is the parking lot for unimplemented surface, moved into `active/` in the same commit that lands each command. Smoke test asserts the current stub binary's "exit 1 / not yet implemented" behavior.
- docs: `docs/TESTING.md` — testing convention covering toolchain (trycmd / assert_cmd / trybuild), the `_pending/` → `active/` promotion rule, mockup-to-scenario conversion recipes, scenario naming, and the trycmd assertion-model quick reference.
- test: `_pending/` scenarios for cross-cutting CLI commands (mockup 06 — F1/F2/F3) — 9 trycmd files covering `aristo rename` (dry-run, actual run, three error paths), `aristo stamp` cycle diagnostics (multi-node cycle, self-cycle, diamond-is-DAG), and `aristo show` (by id, by function name with multi-match disambiguation, by file:line, error paths with did-you-mean / stale-index / empty-result, JSON+TOML structured output).
- test: aligned mockup-06 `_pending/` scenarios to current B5a-revised + B5b + K1 schema — server-bound annotations carry the `aristos:` prefix in source ids and parent references, the per-annotation `sig` field is replaced by `verified_outcome` (Ed25519, `v1:...` form), `linked` opaque uses the `arta_<base32>` form, and `rename_error_cases.md` adds a cross-namespace-rejection scenario per the TOOLS.md rename rule. Mirrors the `aretta-sdk` mockup update commit `49970ea`.
- test: `_pending/` scenarios for `aristo lang` (mockup 12 — K5) — 3 trycmd files covering Rust auto-detection from `Cargo.toml` (full cheat-sheet output), per-file detection via `--file scripts/setup.py` for mixed-language repos (Python; activates with the Phase 2+ Python `LanguageSyntax` impl), and the unsupported-language error path that lists supported + planned languages.
- test: `_pending/` scenarios for `aristo install-skills` + `aristo uninstall-skills` (mockup 12 — K4) — 10 trycmd files covering the two install models (file-copy: `claude-code`, `cursor`, `antigravity`; AGENTS.md section-injection: `codex`, `opencode` reusing the codex block), the `--list-agents` enumerator, the `--update` no-op-when-current path, the `--user` cross-project install, and uninstall for both install models (AGENTS.md section strip; file removal with locally-modified-skip + `--force` advisory).
- test: `_pending/` scenarios for J1/J3/J4/J5/J6/J7 gap-closure UX (mockup 11) — 13 trycmd files covering `aristo list` (basic inventory with stale advisory, J2 unified-grammar `--filter`, JSON output), `aristo verify --audit-only` (offline B5b audit, `--strict` publisher-provenance cross-check, `--check` CI gate), the J2 `--filter` / `--rerun` rework on `aristo verify`, J3 `aristo graph --filter status=`, J4 free-tier `verify="full"` graceful downgrade, J5 uniform stale-index preflight across show/graph/status/doc, J6 `aristo lint --check` / `--fix` direct invocations, and J7's `aristo status` footer hint.
- test: `_pending/` scenarios for `aristo doc` (mockup 10 — I1) — 6 trycmd files covering the first run (per-annotation markdown to `.aristo/doc/<id-safe>.md`), incremental regeneration (only changed files rewritten), `--include-status` (opt-in B5b status bake-in with stale advisory), `--summary` (project-level `_summary.md` for crate-root rustdoc embedding), `--include-graph` (composite: doc + summary + graph SVG via `dot`), and `--check` CI gate that catches drifted doc artifacts.
- test: `_pending/` scenarios for `aristo graph` (mockup 10 — I2) — 11 trycmd files covering output formats (Mermaid stdout default, `--out=<file>`, DOT, SVG via `dot -Tsvg`, missing-`dot` friendly error with platform install hints + non-`dot` alternatives), filtering (subtree by `id=`, per-file with parent context, direct children via `parent=` + `--depth=1`), and visualization modes (`--include-status` color-by-status with state counts, `--exclude-assumes` to focus on the intent graph, composed multi-flag rendering).
- test: `_pending/` scenarios for B5b verification certification (mockup 09) — 6 trycmd files, one per diagnostic state: `verified` (full happy-path: `aristo verify` issuance, `aristo stamp` offline re-validation, `aristo show` certificate block), `stale` (body-hash drift; sig still valid; status reverts to `unknown`; `--check` CI gate fails), `orphan` (`commit_hash` not in this repo; CRITICAL diagnostic; copy-from-other-repo guidance), `forged (tampered)` (sig fails any bundled key — security signal), `forged (key revoked)` (sig valid but key in revocation list — distinguishable from tampered), and `pending-deepen` (shallow-clone soft-warning soft state). Mirrors the `aretta-sdk` mockup-09 alignment commit.
- test: `_pending/` multi-step lifecycle scenarios from `docs/diagrams/01-lifecycle.mmd` — 4 trycmd workflow walkthroughs covering bootstrap (`init` → `install-skills` → `stamp` → free-tier `verify`), paid sync + binding (`auth login` → `sync` adds `aristos:` prefix + writes `verified_outcome` → `show` reveals certificate), pre-push ship artifacts (`doc --include-graph` + `badge`), and the CI gate sequence (`stamp --check` → `verify --check --strict` → `doc --check` → `lint --check --strict`). The state-map and verify-execution diagrams (architecture / decision-tree views) are not converted; their behavior is fully covered by per-command and per-state scenarios.
- feat(core): index types — `IndexFile`, `Meta`, `IndexEntry`, `ParentLink`, plus `AnnotationKind` / `Status` / `VerifyLevel` / `VerifyMethod` / `CoveredRegion` enums. Newtype validators (`Sha256`, `CommitHash`, `ArtaId`, `VerifiedOutcome`, `AnnotationId`) enforce length + prefix + character set on parse via `serde::Deserialize`; cryptographic validity is deferred to the actual signature check (per user direction). `IndexEntry::validate` and `IndexFile::validate` enforce cross-field rules serde can't (`assume` forbids `verify` and server-binding; `aristos:` ids require `linked`). Every type derives `JsonSchema` for the slice-3 codegen pipeline. 46 unit tests cover happy + sad paths.
- refactor(core): drop `anumana:` namespace from `AnnotationId` — the namespace was a speculative reservation for a hypothetical second binding kind that has not materialized. Removes the `ANUMANA_PREFIX` constant, the parse branch, the JSON Schema regex alternation, the doc-comment mention, and the dedicated test. Mirrors the upstream `aretta-sdk` design archive cleanup (commit `4757af2`). 45 unit tests still pass; only the now-removed scenario went away.
