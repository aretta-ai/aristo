## [v0.0.4] — 2026-05-15

**Milestone C — Index pipeline.** The full inspection loop closes. From source to insight without an external tool: walker + hashing + cycle detection in `aristo-core` (slices 14–15), `aristo index` and `aristo stamp` (slices 16–17), `aristo show` and `aristo list` (slice 18). The dogfood loop now runs end-to-end against Aristo's own source: 103 annotations stamp, query, and round-trip through the CLI. Slices 14–18.

### Added
- feat(cli): `aristo show` + `aristo list` (slice 18, closes milestone C) — the inspection layer that closes the FULL DOGFOOD LOOP. Both commands read `.aristo/index.toml`. **`aristo show <selector>`** dispatches on selector form: bare id (`returns_forty_two`, `aristos:foo`, `aret_a1b2c3d4`) returns the full record + reverse-walked children (every annotation that lists this id as `parent`); `fn <name>` / `mod <name>` / `struct <name>` / `enum <name>` / `trait <name>` / `impl <name>` / `type <name>` returns the single matching annotation OR a multi-match disambiguation list (`Found N sites matching ...`); `<file>:<line>` returns the annotation(s) at that exact source line. Bare-id lookups that miss show a Levenshtein-bounded did-you-mean (threshold = `len/3`, capped at 3 suggestions, so unrelated ids never bubble up); `fn name` lookups that miss show a "try `aristo list --filter file=<path>`" hint. Output modes: text (default), `--json` (structured `ShowRecord` mirroring the index schema + `children[]`), `--toml` (mirrors the on-disk index — pipeable with `aristo stamp` for round-trips). The `--json` and `--toml` flags are mutually exclusive (clap `conflicts_with`). The selector parser distinguishes `aristos:thing` (id) from `src/lib.rs:42` (file:line) by requiring the right side of `:` to parse as a u32 — id suffixes never start with a digit (validated by `AnnotationId::parse`). **`aristo list [--filter K=V]... [--json]`** is the flat enumeration. Default text output: one annotation per line with id (left-padded to 20-char floor or longest id, whichever is wider), kind, verify, status; sorted alphabetically by id; footer summary `N annotations  (X intent / Y assume)`. `--filter` clauses use the J2 unified filter grammar from slice 9A (`id=`, `file=`, `parent=`, `status=`); multiple `--filter` flags AND together; unknown filter keys exit 2 with a helpful list of accepted keys. `--json` emits a deterministic `ListRecord[]` array suitable for piping into `jq` / scripts. Both commands surface a clean error when `.aristo/index.toml` is missing (exit 2 with "run `aristo stamp`" hint). Stale-index preflight (J5) is deferred to slice 19, which ships the shared preflight module across all reader commands. The `aristo show` / `aristo list` stubs are gone from `dispatch`; `binary_smoke::defined_but_unimplemented` re-pointed at `aristo status` (slice 19). 18 imperative tests across `tests/show_command.rs` (10) + `tests/list_command.rs` (8) cover error paths / id+selector dispatch / did-you-mean threshold / multi-match disambiguation / `--json` round-trip / multi-`--filter` AND / bad-filter rejection. Three trycmd scenarios promoted from `_pending/` to `active/` with `.in/`-sandbox source fixtures: `show_by_id.md`, `list_basic_inventory.md`, `list_filter.md` (the remaining 5 `_pending/` scenarios — `show_by_function_name`, `show_by_file_line`, `show_error_paths`, `show_structured_output`, `list_json_output` — stay pending until slice 19's stale-preflight + Phase-2 server-binding fields are available, since their mockup outputs lean on those features). Two dogfood `#[aristo::intent]` annotations on the new code (did-you-mean threshold filters noise; matches_filter arms cover the Filter enum). New deps in aristo-cli: `serde = "1.0"` (derive) + `serde_json = "1.0"` (production + dev). 295 tests passing across the workspace; 1 ignored. **Milestone C complete: full inspection loop closes — author with skill → compile (with `aristo_check`) → stamp → show / list.**

- feat(cli): `aristo stamp` (slice 17) — `aristo index` plus body-drift detection plus `--check` CI mode. Reads the existing `.aristo/index.toml` first so it can compare per-entry hashes across runs. For each entry that survives (id present in both old + new): `body_hash` unchanged → status preserved verbatim; `body_hash` drifts AND prior status was `Verified` / `Tested` / `Neural` → status flips to `Stale` (so anything still showing `Verified` after stamp is verified for THIS code, not some prior version of it); text changed but body unchanged → status held with a `review cache invalidated` notable line (text-only edits are a re-review concern, not a re-verify concern). Removed annotations (id absent from new walk) drop from the index; the per-id summary surfaces every transition worth seeing. `--check` runs the full pipeline but does NOT write the index — exits non-zero if entries differ from the on-disk file, gating pre-merge CI on the index being committed in sync with source. The `--check` comparison uses entries + schema_version only, NOT the raw TOML text — `generated_at` / `generated_by` churn every run and would otherwise make `--check` always report "out of sync." **`body_hash` extraction bug fixed in the same commit:** the slice-14B walker hashed entire item spans including the `#[aristo::intent]` attribute, so text-only attribute edits flipped `body_hash` (defeating the whole "text-changed, body-held → status preserved" contract). Now hashes the inner block / fields / brace span / type / module body for each item kind, excluding the attribute itself. 9 imperative tests in `tests/stamp_command.rs` cover fresh-workspace stamp, status preservation when body is unchanged, body-change → Stale flip, text-only edit holds status, removed-annotation drop, `--check` no-write on match, `--check` exit-2 on staleness, `--check` byte-identity preservation of the existing index, and the cycle-aborts-stamp error path. Two dogfood `#[aristo::intent]` annotations on the new code (`--check` never writes the index; merge_status_from_prev preserves status when body is unchanged). Stamp command-routing helpers in `aristo-cli/src/commands/index.rs` made `pub(crate)` so stamp can reuse the workspace lookup, entry builder, atomic writer, and RFC3339 timestamp helper without re-implementation. 269 tests passing across the workspace; 1 ignored.

- feat(cli): `aristo index` (slice 16) — wires the slice-14 walker + slice-15 cycle detector into a CLI command. Walks the workspace, parses every `.rs` file, builds an `IndexFile` (assigning opaque `aret_<random>` ids to annotations without user-written ids — `aristo stamp` (slice 17) layers the offer-rename flow on top), runs cycle detection, writes `.aristo/index.toml` atomically (temp file in same dir + rename, so a crash leaves either the prior or new index intact, never a half-formed file). Permissive mode: invalid annotations (bad id charset, bad verify value, bad parent id) get a `warning: skipping <file>:<line>: <reason>` to stderr and the walk continues; only cycle detection and IO failures are hard errors. This lets the dogfood walk over Aristo's own source succeed despite the trybuild compile-fail fixtures (which intentionally embed malformed annotations as test inputs). `--all` flag is wired through clap and accepted as a no-op for slice 16; the per-file mtime cache lands in slice 17+ so users / CI scripts that already pass `--all` don't break when the cache arrives. Promotes `index_standalone.md` from `_pending/` to `active/` (covers fresh-init walk + `--all` no-op equivalence; the no-workspace error path moves to imperative tests because trycmd's per-file sandbox sharing prevents combining workspace-present and workspace-absent assertions in one scenario). 8 imperative tests in `tests/index_command.rs` cover no-workspace error / meta-only zero-annotation index / single-attribute roundtrip via `aristo-core::IndexFile` parse / opaque-id assignment / permissive mode / cycle error preserves prior index / atomic re-run overwrite / `--all` no-op equivalence. Three dogfood `#[aristo::intent]` annotations on the new code (atomic write, opaque-id assignment, build_entries shape). The dogfood loop now closes end-to-end: `aristo init && aristo index` against the Aristo workspace finds 101 valid annotations + 5 deliberate test-fixture skips. **`.gitignore` updated** to exclude `/aristo.toml` / `/.aristo/` / `/.github/workflows/aristo.yml` (this repo's dogfood artifacts; downstream projects DO commit these by design — only this repo excludes them so the dogfood doesn't churn the tree). 259 tests passing across the workspace; 1 ignored.

- feat(core): cycle detection over the annotation parent graph (slice 15) — `aristo_core::cycle::detect_cycles(&HashMap<AnnotationId, Vec<AnnotationId>>)` returns `Ok(())` for acyclic input or `Err(CycleError { path })` for a cycle. DFS-based, single-pass, allocates only the recursion stack + visited/on_stack sets. Returns the FIRST cycle found and stops — chasing every cycle would multiply diagnostic noise without helping the fix; user breaks the cycle and re-runs. Self-cycles (`a → a`) get the same error type with `path == [a]`. Diamonds are correctly recognized as DAGs (visit-once-per-node, not once-per-path). Orphan parent references (id pointing at a non-existent parent) are NOT cycle errors — those are caught by `aristo stamp`'s separate id-resolution pass with a different diagnostic. `CycleError::Display` renders the cycle as `a -> b -> c -> a` with the closing edge so the user sees the loop visually. 13 unit tests cover empty / linear / self-cycle / 2-cycle / 3-cycle / diamond / multi-component / orphan-parent / multi-parent-with-cycle-branch / 10-node cycle / message rendering / `aristos:` namespace ids. One dogfood `#[aristo::intent]` (the first-cycle-only behavior). Pure logic; zero new deps. 250 tests passing across the workspace.

- feat(core): filesystem walker (slice 14C, closes slice 14) — `aristo_core::walk::walk_directory(root)` walks the filesystem from a project root, finds every `.rs` file, parses each via the slice-14B extractor, and returns `Vec<DiscoveredAnnotation>` (each carrying its file path relative to the walk root). Built-in skip set: `target/` / `.git/` / `.aristo/` / `node_modules/` (matched by basename, so `vendor/target/` is also skipped). Output is byte-identical across runs and across machines: files in lexicographic path order via `walkdir`'s `sort_by_file_name`, annotations within each file in source order. IO failures and parse failures abort the walk and surface the offending path via `FsWalkError::{Io, Parse}`. Nonexistent root → `FsWalkError::BadRoot`. 7 unit tests cover multi-file aggregation, ignored-directory enforcement (4 separate skip-paths verified independently), no-rust / no-annotations short-circuit, deeply nested file discovery, byte-identical re-walk, parse-error path attribution. One dogfood `#[aristo::intent]` (the determinism guarantee). Deps added to aristo-core: `walkdir = "2.5"`; `tempfile = "3.10"` as dev-dep for the tests. Slice 14 closed: hashing + id generation + AST extraction + filesystem walk now ship as a complete library, ready for slice 16 (`aristo index`) to wire through to the CLI. 237 tests passing across the workspace.
- feat(core): annotation extraction from Rust source (slice 14B) — the AST-walking layer that finds annotations in a source string. New `aristo_core::walk::extract::extract_from_source(&str)` parses Rust via `syn` and returns `Vec<ExtractedAnnotation>` covering both attribute forms (`#[aristo::intent(...)]` / `#[aristo::assume(...)]`) and statement forms (`aristo::intent_stmt!(...)` / `aristo::assume_stmt!(...)`); both fully-qualified `aristo::*` paths and bare-imported variants (after `use aristo::intent;`) are recognized. Recurses into impls (inherent and trait), trait method declarations, inline modules, and fn bodies (including for / while / loop / if branches) to surface every annotation. Each `ExtractedAnnotation` carries kind / form / text / verify / parent / id / site label (e.g. `"fn balance_non_root"`, `"impl Holder::new"`, `"trait Doublable::doubled"`) / line / covered-region kind / text_hash / body_hash. Parent values support both singular `parent = "x"` and list `parent = ["a", "b"]` forms. Annotations return in source order — the downstream walker depends on this for stable index.toml ordering when ids haven't been assigned. Malformed annotation args are silently skipped (the proc-macro layer emits the `compile_error!` for the same input — walker would double-emit). Truly malformed Rust source returns `ExtractError::Parse` from `syn`. 25 unit tests cover each surface form, parent shapes, verify-value token capture (`"true"` / `"\"neural\""`), bare-import variants, multi-annotation source-order preservation, body-hash drift on body change, and the no-aristo-attrs-found case. Two dogfood `#[aristo::intent]` annotations on the new code (source-order guarantee, body-hash drift behavior). Deps added to aristo-core: `syn = "2.0"` (full / extra-traits / visit features) and `proc-macro2 = "1.0"` (span-locations feature).
- feat(core): hashing + id-generation helpers (slice 14A) — pure-function building blocks for the upcoming `aristo index` / `aristo stamp` commands. New `Sha256::from_bytes(&[u8])` constructor produces canonical `sha256:<64 lowercase hex>` form (round-trips through `Sha256::parse`). New `aristo_core::hash` module: `text_hash` normalizes whitespace before hashing (trims edges, collapses runs into single spaces) so `aristo lint --fix`-style reformatting doesn't invalidate stamped annotations; `body_hash` is verbatim — every byte of the covered region counts, so any source change in the body (even cosmetic) flips status to `unknown` and prompts re-verify (this is by design per B5b drift detection). New `aristo_core::id` module: `snake_case_from_text` derives a readable id suggestion from annotation text (lowercases, collapses non-alphanumeric runs into underscores, caps at 32 chars, prepends `n_` if the input starts with a digit, returns `None` for empty/punctuation-only/non-ASCII-only input); `generate_opaque_id` returns an `aret_<8 chars>` `AnnotationId` with 40 bits of entropy from the OS RNG (panics if RNG fails — better than emitting a low-entropy id). 21 unit tests across the two modules. The first dogfood `#[aristo::intent]` annotations on `aristo-core` source land here (4 invariant statements covering canonical-form guarantee, whitespace-normalization rule, body-verbatim rule, opaque-id always-parses guarantee). New deps: `aristo` (for the macro re-export), `getrandom = "0.2"` (lightweight OS-RNG wrapper, no `rand` crate weight), `sha2 = "0.10"`.

## [v0.0.2] — 2026-05-15

**Milestone A — Macro foundation.** The `#[aristo::intent]` / `#[aristo::assume]` proc-macros (attribute and statement-position forms) compile, validate, and dogfood on Aristo's own source. The `aristo` CLI binary now dispatches via `clap` to 16 offline-scope subcommand stubs, each pointing at the roadmap slice that lands its real handler. Slices 6–9.

### Added
- feat(macros): `#[aristo::intent]` attribute macro — slice 6B. Parses the canonical argument shape (positional `text` string literal, then key=value `verify` / `parent` / `id`) matching the subset of `IntentEntry` developers write by hand; `aristo stamp` populates the rest from source position. Slice 6 is pass-through expansion only — the macro emits the wrapped item unchanged. Validation lands with the `aristo_check` cargo feature in slice 8; trybuild compile-fail tests in slice 7. Applies to fn / impl / struct / trait / type / mod (and trait impl bodies) per mockup 01. `proc-macro2 = "1.0"` / `quote = "1.0"` / `syn = "2.0"` (feature `full`) added to `aristo-macros` deps.
- feat(macros): `#[aristo::assume]` attribute macro — slice 6C. Same shape as `#[aristo::intent]` minus `verify` (per A5: assumptions describe invariants the code RELIES ON — OS guarantees, library contracts, upstream caller promises — they are not verification targets). Passing `verify =` to `assume` is rejected at parse time with a category-error message that points the user at `intent` instead. Pass-through expansion; same item-surface coverage as `intent` (fn, impl, struct, trait, trait impl, type alias, mod).
- feat(macros): `aristo::intent_stmt!()` function-like macro — slice 6D. Statement-position annotation form for sub-item intents (inside fn bodies, before stmts/loops/blocks) where the attribute form can't reach. Reuses the `IntentArgs` parser; expands to an empty token stream — purely a compile-time annotation, zero runtime trace. Naming differs from the mockup-01 sketch (`intent!`) because Rust requires distinct fn names for attribute and function-like proc-macros within a single crate (E0428); we follow ecosystem convention (tokio: `#[main]` + `select!`; tracing: `#[instrument]` + `trace!`) and use the `_stmt` suffix to make the statement-position context explicit at the call site.
- feat(macros): `aristo::assume_stmt!()` function-like macro — slice 6E. Statement-position assumption form mirroring `intent_stmt!` minus `verify` (A5). Empty expansion, zero runtime trace.
- feat(aristo): re-export the four annotation macros from the meta-crate — slice 6F. Downstream users add `aristo` to `Cargo.toml` and write `use aristo::{intent, assume, intent_stmt, assume_stmt};` (or use FQ paths like `#[aristo::intent(...)]` and `aristo::intent_stmt!(...)`) without ever needing to know that the macros physically live in `aristo-macros`. Closes slice 6 — the macro foundation is in place; from this point onward, new code on Aristo's own source carries `#[aristo::intent]` / `#[aristo::assume]` annotations per the §10 discipline.
- test(macros): trybuild compile-pass UI test suite — slice 7. 7 fixture files under `crates/aristo-macros/tests/ui/pass/` exercise every advertised surface form (intent attribute on fn / struct / impl / trait / trait impl / type alias / mod; assume attribute on the same; intent_stmt!/assume_stmt! in stmt / block / loop / branch positions; all 4 verify shapes — true/false/three string values; singular and list parent; explicit id; the canonical mockup-01 balance_non_root with nested intent_stmt). Each fixture is compiled as its own program by trybuild — a regression in any one surface fails an isolated case rather than a megablob. Compile-fail cases (locked .stderr snapshots) follow with the `aristo_check` cargo feature in slice 8. `trybuild = "1.0"` added to `aristo-macros` dev-dependencies; `aristo` registered as a workspace member dependency for use in `dev-dependencies`. Closes pre-roadmap pending task #10.

Users who want zero validation cost can disable via `aristo = { default-features = false }`. Validators (in `aristo-macros::validate`): text non-empty (after `trim`); `verify` (if present) must be a bool literal or one of `"false"` / `"test"` / `"neural"` / `"full"`; `id` (if present) must NOT start with `aret_` or `aristos:` (those are tool-managed by `aristo stamp` / `aristo sync`) and must be valid snake_case (lowercase ASCII + digits + underscores, leading letter). Multiple errors on one invocation chain via `syn::Error::combine` and surface together. 16 unit tests for the validator helpers (parse → validate → assert error message) plus 10 trybuild compile-fail UI fixtures with locked `.stderr` snapshots covering each rule plus the multi-error-combine path.
